# 免费额度怎么花,以及怎么不超标

## 一、硬事实(2026-10 核实)

| 项目 | 免费额度 | 备注 |
|---|---|---|
| Workers 请求 | 100,000 / 天 | 每分钟还有 1,000 次的软限制 |
| Workers CPU | **10 ms / 请求** | 等网络的时间不算 CPU |
| Workers 内存 | 128 MB | |
| 子请求 | 50 / 请求 | 一次 fetch 算一个 |
| 并发外连 | 6 / 请求 | |
| 脚本大小 | 64 MiB | 本项目只有几百 KB |
| Durable Object | 100,000 请求 / 天 | **免费套餐可用**(只能用 SQLite 后端) |
| DO 存储 | 5 GB | |
| DO CPU | 30 秒 / 次调用 | 闹钟同样适用 |
| DO 闹钟墙钟时间 | **15 分钟 / 次** | 这是我们敢跑长任务的底气 |
| 定时任务 | 5 个 / 账号 | |
| 日志 | 200,000 事件 / 天 | Workers Logs |

关键的两条:

- **HTTP 请求的墙钟时间不限**,只要客户端还连着
- **`ctx.waitUntil` 只在响应之后额外给 30 秒** —— 所以长任务不能靠它

## 二、这个项目怎么省 CPU

免费套餐只有 **10 ms CPU / 请求**,而解析 JSON 是实打实吃 CPU 的。

### 1. 前台 Worker 只干三件事

```
验签(一次 Ed25519 verify)→ 把事件丢进 Durable Object → 回 200
```

实测不到 3 ms。重活全在 DO 里,DO 有 30 秒 CPU 预算。

### 2. 用非流式请求,一次拿完

QQ 消息本身不支持流式输出,流式拿到的分片最终也只能攒成一段文本再发出去。
所以这里统一发非流式请求:一次响应、一次 `JSON.parse`,CPU 占用比逐分片解析低一个量级。

### 2.5 解析尽量少做无用功

响应里真正要用的是 `content`、`reasoning_content`、`tool_calls` 和 `usage` 四个字段,
解析函数只做这一件事,不遍历、不复制大字符串。

### 3. 思考日志只留前 1500 字

`reasoning_content` 可能有几万字,全存进日志既浪费内存也浪费日志配额。
只保留开头 1.5K 字 + 总长度统计。

### 4. 上下文有上限

- 每个会话只保留最近 12 条消息
- 超过 6000 字自动压缩成摘要(阈值在 `src/config.js`)
- 部署代码单站点上限 200 KB

## 三、为什么不会「持续占用资源」

Durable Object 是**按需唤醒**的:

- 没有消息进来 → 完全休眠,不消耗 CPU、不消耗请求数
- 有人访问部署页面 → 只唤醒一次做一次 SQLite 查询
- 闹钟只在「有任务」或「有站点要过期」的时候才被设置

部署出来的页面是纯静态的,一次请求就是一次 SQLite 读,不跑任何用户代码。

## 四、什么时候会超标

| 场景 | 会不会超标 |
|---|---|
| 几百人的群日常聊天 | 不会。一天几百条消息 × 2 次请求 = 几千 |
| 部署的页面被大量访问 | 有风险。每次访问 = 1 次 Worker 请求 + 1 次 DO 请求 |
| 一天 10 万条以上群消息 | 会。但那时候该考虑付费版了 |

如果真的把页面分享出去被疯狂访问,可以:

1. 缩短部署存活时长
2. 减少同时在线部署名额(都在 `src/config.js` 的 `FIXED` 里)
3. 给部署页面加 CDN 缓存(改 `src/serve.js` 里的 `Cache-Control`)

## 五、真正会先耗尽的不是 Cloudflare

按默认配置,一次问答大约消耗:

- 1 次 QQ 回调请求
- 1~2 次 DO 请求
- 1~6 次上游模型调用(取决于工具调用轮数)
- 1~5 次 QQ 发消息

**上游大模型网关的额度会先见底**,不是 Cloudflare。
在 Cloudflare 后台看 Workers 用量,或者在你自己的上游网关后台看额度消耗。

## 六、如果还是不够用

用户提到的 IBM 免费服务器之类的方案可以做,但要注意:

- 免费服务器通常有**休眠策略**(闲置就睡),而 QQ 的 WebSocket 长连接会被掐断
- 如果改用 WebSocket 模式(而不是 Webhook),就需要一个常驻进程,
  而且 Durable Object 一直醒着会吃掉免费时长的绝大部分
- 本项目刻意选了 **Webhook + Durable Object 闹钟** 这套无状态方案,
  就是为了「没人用的时候一点资源都不占」

真到了需要扩容的时候,更划算的做法是给 Cloudflare 升到 $5/月的付费版:
CPU 从 10 ms 涨到 30 秒,请求数也基本不封顶。
