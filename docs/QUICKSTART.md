# 新手部署教程(约 15 分钟)

从零开始,把一个 QQ 机器人跑起来。不需要服务器、不需要域名、不需要会写代码,
只要一个 Cloudflare 账号(免费版够用)和一个 QQ 机器人账号。

> 想先知道这东西能干什么,看 [README](../README.md)。
> 卡住了,先翻 [FAQ](FAQ.md);要更细的说明,看 [DEPLOY](DEPLOY.md)。

---

## 开始之前,先确认这三件事

| 需要 | 说明 |
| --- | --- |
| Cloudflare 账号 | 免费注册,免费套餐足够跑这个项目 |
| GitHub 账号 | 用来 Fork 仓库,Cloudflare 从仓库自动构建 |
| QQ 机器人账号 | 在 [QQ 开放平台](https://q.qq.com/qqbot) 注册,拿到 APPID 和 AppSecret |

还需要一点点耐心:第一次配置大概 10 到 15 分钟,后面改配置都在网页面板里点。

---

## 第 1 步:把仓库 Fork 到自己名下

1. 打开仓库页面,点右上角 **Fork**
2. 所有者选你自己,仓库名保持默认,点 **Create fork**

> 为什么要 Fork?Cloudflare 要连一个**你自己的**仓库,才能在你的账号下自动构建。
> 直接连别人的仓库也能部署,但以后更新会被别人的改动影响。

---

## 第 2 步:创建 Worker 并连上仓库

1. 打开 [Cloudflare 控制台](https://dash.cloudflare.com/) → **Workers & Pages**
2. 点 **Create** → **Workers** → **Connect to Git**
3. 授权 GitHub,选中你刚 Fork 的仓库,点 **Begin setup**
4. 构建配置保持默认即可:
   - **Build command**:留空或填 `npm run build`(两者都会在构建时清理描述文件)
   - **Deploy command**:`npx wrangler deploy`
5. 点 **Deploy**

等一两分钟,构建日志最后出现 `Deployed` 就成功了。
你的地址形如:

```
https://nomo-qqbot.<你的账号子域>.workers.dev
```

> 第一次打开可能是 503,这是正常的 —— 数据库还没绑,继续往下走。

---

## 第 3 步:创建 D1 和 KV(必须),R2 可选

在 Cloudflare 控制台左侧进 **Storage & Databases**:

| 类型 | 名字 | 必须? | 用途 |
| --- | --- | --- | --- |
| D1 | `nomo-qqbot` | 必须 | 配置、日志、统计、项目清单 |
| KV | `nomo-qqbot-store` | 必须 | 部署出来的网页文件 |
| R2 | `nomo-qqbot` | 可选 | 文件优先存这里,免费 10 GB |

点 **Create** 一个个建好,名字可以不一样,但下面绑定时的**变量名**必须对。

---

## 第 4 步:把数据库绑到 Worker

回到你的 Worker → **Settings** → **Bindings** → **Add binding**:

| 类型 | 变量名(必须一字不差) | 选什么 |
| --- | --- | --- |
| D1 database | `DB` | 第 3 步建的 D1 |
| KV namespace | `STORE` | 第 3 步建的 KV |
| R2 bucket(可选) | `R2` | 第 3 步建的 R2 |

> 变量名写错(比如 `db`、`KV`)等于没绑,后面会一直报错。
> 绑完点一次 **Deployments → Retry deployment**,让绑定生效。

---

## 第 5 步:设置管理员账号

还是 Worker → **Settings** → **Variables and Secrets** → **Add**:

| 变量名 | 填什么 | 类型 |
| --- | --- | --- |
| `ADMIN_USER` | 面板登录用户名,自己定 | Secret |
| `ADMIN_PASS` | 面板登录密码,建议 16 位以上随机串 | Secret |

只有这两个环境变量。AI 接口、QQ 凭据、搜索 Key 全都在面板里填,存进 D1,
以后改配置不用重新部署。

> 本仓库已在 `wrangler.toml` 里设置 `keep_vars = true`,以后部署不会清掉后台变量。
> 如果之前变量被旧版空 `[vars]` 删掉了,重新添加一次即可,不需要改代码。

> 千万不要把密码写进 `wrangler.toml` 再提交到公开仓库。

加完变量后**再部署一次**(Deployments → Retry deployment)。

---

## 第 6 步:第一次打开面板

浏览器打开:

```
https://<你的地址>/administrator
```

用第 5 步的账号密码登录。

如果看到「登录功能已关闭」,说明 `ADMIN_USER` / `ADMIN_PASS` 没生效:
检查变量加在**当前 Worker** 上,并且重新部署过。

---

## 第 7 步:配置 AI 接口

进 **设置 → AI 接口**:

1. **接口地址**:填到 `/v1` 那一层,例如 `https://api.example.com/v1`
   - 不写 `https://` 也行,保存时会自动补
   - 粘贴了完整的 `/chat/completions` 也会自动去掉
2. **API Key**:填你的密钥
3. 点 **获取模型列表**,从返回的模型里点一个,自动填进「模型 ID」
4. 点 **测试模型**,弹窗里会跑两项:
   - 基础对话:能不能正常回复
   - 工具调用:能不能正确调用函数(部署网页、搜索都靠它)
5. 两项都绿了,点 **保存**

> 如果基础对话失败:先检查地址是不是填到了 `/v1`,Key 有没有多余空格。
> 如果工具调用失败:这个模型可能不支持 function calling,换一个模型。
> 有些中转站会拦截 Cloudflare 的出口 IP,这种情况只能在面板的报错里看出来。

---

## 第 8 步:配置 QQ 机器人

还在 **设置** 页,往下找到 **QQ 机器人**:

1. 填 **APPID** 和 **App Secret**
   (QQ 开放平台 → 你的机器人 → 开发设置 → 机器人资料)
2. **运行环境**:已经上线选「正式环境」;还在调试选「沙箱环境」
3. **连接方式**保持 **WebHook**
4. 复制面板显示的**回调地址**,填到:
   QQ 开放平台 → 开发设置 → **回调配置**
5. 在回调配置里至少勾选这些事件:
   - `GROUP_AT_MESSAGE_CREATE`(群里 @ 机器人)
   - `C2C_MESSAGE_CREATE`(单聊)
   - `GROUP_ADD_ROBOT`(被拉进群)
6. 回到面板点 **保存并应用**

> 回调地址必须是 **HTTPS**,端口必须是 443。
> `workers.dev` 和绑定了 Cloudflare 的自定义域名都满足。
>
> 保存回调时腾讯会发一个验证请求。如果提示校验失败,通常是 Cloudflare 的
> 托管质询把腾讯服务器拦住了 —— 在 CF 后台加一条 WAF Skip 规则跳过
> `/qq/webhook`,或者干脆把连接方式切成 **WebSocket**(不需要回调地址)。

---

## 第 9 步:在群里说第一句话

1. 把机器人拉进一个群(你是群主/管理员)
2. 在群里 @机器人 发:

```
/查信息
```

它会回你的 openID 和群聊 openID。

3. 把群聊 openID 填到 **设置 → 群聊权限**,或者直接打开 **允许所有群聊**
4. 再发:

```
@机器人 /AI 你好,介绍一下你自己
```

能正常回答,就说明整条链路通了。

---

## 第 10 步(可选):把体验补完整

按需配置,不配也能用:

- **联网搜索**:设置 → 联网搜索,填到 `/v1` 那一层的地址和 Key,
  点「测试搜索与读取」。
- **站点域名**:设置 → 部署参数 → 站点域名,填你的公开地址
  (比如 `https://nomo-qqbot.xxx.workers.dev`)。填了之后,机器人给的部署链接
  才是完整可点的网址。
- **部署架构**:设置 → 部署架构,决定机器人能不能部署网页、能不能调后端。
- **人设提示词**:设置 → 人设提示词,改机器人的说话风格。

## 以后怎么更新(OTA)

这个项目有两种更新方式:

| 你的部署方式 | 怎么更新 |
| --- | --- |
| 连了 GitHub 仓库(推荐) | 往仓库推一次提交,Cloudflare 自动重新构建部署 |
| 本地克隆 | `git pull` 后 `npm run deploy` |

更新**不会**动 D1 / KV / R2 里的数据:配置、项目、日志都还在。
构建失败可以在 **Deployments** 里回滚到上一个版本。

> 仓库里的 `tools/strip-docs.js` 会在 Cloudflare 构建时清理 README、docs 等
> 描述文件。它只在构建环境里生效,不会动你本地仓库;也不影响 Worker 的体积,
> 因为 Workers 只打包被 `import` 的代码。

## 本地开发(可选)

```bash
npm install
printf 'ADMIN_USER=admin\nADMIN_PASS=本地密码\n' > .dev.vars
npm run dev
```

`.dev.vars` 已经在 `.gitignore` 里,不会被提交。线上不要用它,线上用 Secret。

## 出问题先看这张表

| 现象 | 先检查什么 |
| --- | --- |
| 打开任何地址都是 503 | D1 / KV 没绑,或 `ADMIN_USER` / `ADMIN_PASS` 没设置 |
| 面板显示「登录功能已关闭」 | 管理员变量没生效,重新部署一次 |
| 保存设置报错 | `DB` 绑定缺失,或变量名不是 `DB` |
| 测试模型失败 | 地址没填到 `/v1`、Key 错误、中转站拦了 Cloudflare |
| 群里 @ 没反应 | 群没授权;或回调没配上;或 Cloudflare 质询拦了腾讯 |
| 机器人回「还没有配置 AI 接口」 | 面板里的 AI 地址 / Key 没保存成功 |
| 搜索没结果 | 搜索地址没填到 `/v1`,或服务商返回结构不识别(看测试弹窗) |
| 部署链接打不开 | 项目过期(默认 10 分钟);或站点域名填错 |
| 更新后配置丢了 | 旧版 `[vars]` 空值覆盖了后台;本仓库已加 `keep_vars = true`,重新添加一次即可 |

更多「现象 → 原因 → 解决」在 [FAQ](FAQ.md)。

## 完成检查清单

部署完成后,逐条打勾:

- [ ] `https://<地址>/administrator` 能打开并登录
- [ ] 首页能看到系统信息,没有红色报错
- [ ] AI 接口「测试模型」两项都通过
- [ ] QQ 机器人保存后显示已应用
- [ ] 开放平台回调校验通过(或已切 WebSocket)
- [ ] 群里 `/查信息` 有回复
- [ ] 群里 `/AI 你好` 有回复
- [ ] 群聊权限已授权(或开了允许所有群聊)
- [ ] (可选)联网搜索测试通过
- [ ] (可选)站点域名已填,部署链接完整可点

全部打勾,就可以把机器人拉进更多群了。
