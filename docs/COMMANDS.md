# 指令与工具参考

## 群里怎么用

只有 **@机器人** 之后的内容才会被处理(单聊直接说话即可)。

```
@机器人 /AI 你的问题        → 和 AI 对话
@机器人 你的问题            → 同上(/AI 可以省略)
@机器人 /帮助               → 指令列表
@机器人                     → 只 @ 不说话,也会回指令列表
```

## 指令一览

| 指令 | 别名 | 作用 |
|---|---|---|
| `/AI <内容>` | `/a`、`/问`、`/ask` | 交给 Agent 处理 |
| `/帮助` | `/help`、`/菜单`、`/指令`、`/?` | 显示指令列表 |
| `/压缩` | `/compress`、`/总结`、`/compact` | 把聊天记录压成摘要(省 token 但不忘事) |
| `/delete` | `/del`、`/清除`、`/清空`、`/reset`、`/删除` | 清空这个会话的全部记忆 |
| `/记忆` | `/memory`、`/备忘`、`/memo` | 看机器人记住了哪些事 |
| `/状态` | `/status`、`/info` | 看当前会话与运行状态 |

全角斜杠 `／` 也认。指令不区分大小写。

### `/压缩` 和 `/delete` 的区别

- **`/压缩`**:历史消息交给模型压成一份 400 字以内的摘要,保留最近 4 条原文。
  以后每次对话都会把摘要作为背景注入。适合长期用的群,既能记住关键信息又不撑爆上下文。
- **`/delete`**:彻底删掉这个会话的摘要和全部历史,什么都不留。

另外,当上下文累计超过 6000 字时会自动压缩一次(阈值写在 `src/config.js`)。

## 工具(模型自己决定什么时候调)

| 工具 | 用途 | 什么时候用 |
|---|---|---|
| `deploy_site` | 把代码部署成网页,返回链接 | 用户要小游戏 / 网页 / 工具 |
| `update_site` | 改已部署的页面,链接不变,倒计时重置 | 用户说「改一下」「再加个功能」 |
| `list_sites` | 列出当前所有部署 | 用户问「有几个项目」 |
| `read_site` | 读某个部署的源码 | 改代码前先看一眼 |
| `delete_site` | 删除部署 | 用户说「删掉那个网页」 |
| `web_search` | 联网搜索(走你配置的搜索服务) | 需要最新消息 / 实时数据 |
| `fetch_url` | 抓网页正文 | 已知具体网址 |
| `query_dashboard` | 查 AI 中转站额度用量 | 用户问「还剩多少额度」 |
| `remember` | 长期记住一条信息 | 用户说「记住 xxx」 |
| `recall` | 查看已记住的内容 | 用户问「你记得什么」 |
| `forget` | 忘掉一条记忆 | 用户说「不用记着了」 |
| `random` | 掷骰子 / 抽签 / 随机数 | 需要随机挑一个 |
| `encode` | Base64 / URL / 十六进制互转,JSON 格式化 | 处理编码内容 |
| `calc` | 精确计算数学表达式 | 任何算术 |
| `now` | 当前时间(北京时间) | 涉及「今天」「现在」 |

一轮对话最多 6 次「模型 → 工具 → 模型」往返,每次最多并行 4 个工具。

## 消息是怎么发出来的

一次对话会发两条消息:

1. **回执** —— 收到消息后立刻回一句「🤖 Agent 正在运行,请稍等…」,让群里知道机器人没死。
   这条走**被动回复**(带上消息 ID),因为它就是对刚收到那条消息的直接回应。
2. **结果** —— 模型跑完之后,用**主动消息**把正文发出去,不占用被动回复的次数。

两边都有兜底:被动回复失败(超过 5 分钟或超过 5 次)会自动改用主动消息;
主动消息发不出去(没权限、被限频、用户关闭了接收)会自动退回被动回复。
日志里会打 `[发送] xxx 一条都没发出去,改用 xxx 重试`,消息不会丢。

**单聊固定用被动回复** —— 单聊的主动消息限制更严,而且用户可以在 QQ 客户端里直接关掉接收。

### 频率限制(按已认证开发者口径)

| 类型 | 限制 |
|---|---|
| 被动消息 | 群聊:5 分钟内有效,每条消息最多回 5 次;单聊:60 分钟内有效 |
| 主动消息 | 约 60 次请求/分钟;单个群 20 条/分钟;单个群每天最多 1000 条 |

一轮对话消耗 1 条被动回复(回执)+ 1~N 条主动消息(结果被切分时)。按单群 20 条/分钟算,
一个群每分钟大约能服务 10 轮左右,日常使用完全够。

## 部署出来的网页

链接形如 `https://ai.example.com/ab3k9m2p`(8 位纯英文数字,已去掉容易看错的 `0 o l 1 i`)。

### 静态文件

AI 会写 `index.html`,也可以加 `style.css`、`app.js`、图片(SVG/Base64)等。
路径按目录直接访问:`/<ID>/style.css`。

### 内置后端 `./__data/<键>`

不需要自己搭服务端,前端可以直接存取数据:

```js
// 读
const r = await fetch('./__data/leaderboard');
const data = await r.json();          // 没写过的键返回 404

// 写
await fetch('./__data/leaderboard', {
  method: 'POST',
  body: JSON.stringify([{ name: '小明', score: 128 }]),
});
```

限制:单个键的值不超过 100 KB,每个站点最多 200 个键。
数据跟着站点走,站点被销毁时一起删除。

### 生命周期

- 最多同时存在 **6 个**
- 每个活 **10 分钟**,到期自动删除
- 期间任何修改都会重新计时(上面这些数字都在 `src/config.js` 里)
- 名额满了会淘汰「**最久没有被修改**」的那一个(刚建的不算),并把这件事告诉用户
- 项目过期后访问会看到一个友好的 404 页面
